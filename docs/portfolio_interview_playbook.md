## 一、30 秒面试电梯演讲（Elevator Pitch）

> “您好，我主导设计并研发了一套基于 **LangGraph 状态机 + FastAPI 微服务 + 虚幻引擎 5.8 原生 MCP** 的工业级多智能体自动化资产与玩法装配流水线。
> 
> 针对传统游戏制作中‘资产导入装配繁琐、SOP 规范易出错、缺乏跨 DCC 自动化协同’的痛点，该项目采用 **Supervisor 主管多智能体架构**：通过混合 RAG 对齐工作室资产规范，自动协调资产 TA 智能体（完成网格、材质、Nanite 与碰撞体前置处理）与玩法逻辑智能体（基于 UE 5.8 独有的 `write_graph_dsl` 动态生成并编译蓝图节点图），实现从裸模型到关卡可玩交互实体的全自动闭环。
> 
> 同时，在系统工程上构建了**不可篡改的 Audit Trail 审计链**、**基于 LangGraph Checkpointer 的 Lead TA 人机协同审批门禁**、以及**确定性自愈修复循环**，支持在内网私有双机集群或作为微服务接入 Maya、Houdini 及 CI/CD 流水线。”

## 二、大厂简历核心项目经历撰写模板（Bullet Points）

你可以将以下要点直接整合到个人简历的【核心项目】模块中：

### 项目名称：基于 LangGraph 与 UE 5.8 原生 MCP 的多智能体游戏生产流水线中枢
**角色**：资深技术美术 (TA) / 核心管线架构师 (Pipeline TD)

* **前沿多智能体系统架构（Multi-Agent System）**：
  设计并实现了基于 **LangGraph 纯异步认知状态机** 的工业级 Supervisor 主管分发流水线，将自然语言需求自主拆解为标准化工作分解结构（WBS），实现【资产 TA 智能体】与【玩法逻辑智能体】的确定性拓扑协同。
* **虚幻 5.8 原生 MCP 深度穿透与蓝图代码化编译**：
  深度适配 Epic 官方 Streamable HTTP JSON-RPC 2.0 协议，首创通过 `BlueprintTools.write_graph_dsl` 实现蓝图节点图的文本化生成与热编译，打通了从几何体参数化配资到关卡可交互 Actor 视口布设的最后一公里。
* **企业级风控与 Human-in-the-Loop 安全门禁**：
  针对商业项目资产误删风险，开发了基于规则引擎与意图识别的高危拦截门禁，结合 **LangGraph Checkpoint 持久化挂起与恢复机制**，支持通过 RESTful Webhook 远程进行 Lead TA 安全授权，杜绝无约束 AI 对工程资产的破坏。
* **闭环自愈修复（Self-Healing Reflection Loop）**：
  构建了基于错误 Traceback 诊断的反射补偿闭环（`reflect_and_patch`），当引擎工具调用遭遇参数异常或环境冲突时，智能体自主修正重试，保障流水线在无人值守下的高可用交付率。
* **跨 DCC 零依赖微服务网关（FastAPI + SSE）**：
  封装了具备 OpenAPI / Swagger 文档的标准 RESTful 接口与 Server-Sent Events (SSE) 实时事件流，外部 DCC（Maya/Houdini/Blender）及前端看板无需安装 AI 权重与向量库，仅凭标准 HTTP 请求即可实时驱动引擎装配流水线。
* **私有局域网双机安全协同与 SOP 知识库（Hybrid RAG）**：
  基于 Windows 引擎宿主与局域网 Mac M5 私有推理节点，搭建 ChromaDB 向量库与 BM25 关键词联合检索（RRF 倒排融合算法），100% 离线内网运行，保障游戏核心商业机密零外泄。

## 三、面试高频硬核 Q&A 攻防宝典

### Q1: 为什么不用单一 Agent，而要费力设计 Supervisor 多智能体架构？
> **回答要点**：
> 1. **职责单一性与上下文保鲜**：单一 Agent 面对“既要查资产规范、又要生成蓝图逻辑、还要管关卡摆放”的复杂需求时，Prompt 极度臃肿，Token 消耗剧增，小模型极易出现指令遗忘和幻觉；
> 2. **工序确定性（WBS）**：在游戏工业化流水线中，“先有合格资产，后有玩法绑定”是有严格前后序关系的。Supervisor 模式可以在顶层制定工作分解结构，保证各环节输出通过强契约（State Contract）严格校验后方可流入下一阶段。

### Q2: 你们是如何解决大模型生成蓝图逻辑不可靠的问题的？
> **回答要点**：
> 1. 过去社区尝试让 AI 自动连蓝图，通常采用点击 UI 或脆弱的 Python 模拟，极易断线且无法跨版本维护；
> 2. 我们利用了 **Unreal Engine 5.8 最新的核心突破——文本化蓝图 DSL (`write_graph_dsl`)**。DSL 是结构化、强类型的文本规范，非常契合大语言模型的代码生成优势；
> 3. 配合我们的 **自愈闭环（Self-Healing）**，若编译出现引脚不匹配，错误信息自动反馈给 `reflect` 节点，模型根据规范补丁在毫秒级内自动修正重试。

### Q3: 在大型团队协同（如千人团队 Perforce 主干）中，AI 误删核心资产怎么办？
> **回答要点**：
> 1. **零信任拦截策略**：任何涉及 `delete`、`clean`、`batch_rename` 或未在白名单内的变更，自动触发状态机的 `interrupt_before=["gate"]`；
> 2. **异步挂起与解挂机制**：利用 LangGraph 的 MemorySaver/SqliteSaver Checkpointer 保存当前会话切片，任务状态置为 `WAITING_APPROVAL`；
> 3. **人机协同授权**：通过我们的 FastAPI `/jobs/{id}/approve` 接口，必须由具备权限的 Lead TA 或制作人通过管理后台或飞书机器人完成数字签名审批，工作流方可从当前断点继续执行，否则强制回滚中止。

### Q4: 为什么要自己做一套 FastAPI 服务，而不直接在引擎里开聊天框插件？
> **回答要点**：
> 1. **全链路协同（Multi-DCC Hub）**：现代游戏制作不是只有 UE，还有 Maya 绑骨、Houdini 程序化地形、Blender 白模。如果做成引擎内单一插件，外部软件根本无法调度；
> 2. **算力与依赖解耦**：LangGraph、PyTorch、ChromaDB 等重量级依赖运行在独立微服务中，不需要污染虚幻引擎自带的嵌入式 Python 环境；
> 3. **实时可观测性（Observability）**：FastAPI 提供标准 SSE 接口，可以让 Web 看板、移动端审批流、以及引擎内的 Slate 控件同时接收逐字日志流与节点状态机动画。
